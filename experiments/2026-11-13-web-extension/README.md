# 브라우저 확장 실험: claude.ai 답변을 THYNK로 (2026-11-13)

사용자 요청(11-13): CLI 말고 웹에서 쓴 대화도 편하게 모으기. 1단계 = 폴더로 끼워서 동작 확인 (스토어 등록·설치 파일 자동 등록은 그 뒤, 사용자 결정).

## 만든 것

- `extension/` (크롬·엣지 MV3): claude.ai에서 **새로 끝난** 답변과 그 앞 질문을 `127.0.0.1:8765/api/ingest`로만 보낸다. 열 때 이미 있던 답은 보내지 않는다 (팝업의 '이 대화 답변 전부 보내기'로만).
- 팝업: 기록 중 / 멈춤, THYNK 연결, 오늘 보낸 답변, 대기 중(서버가 꺼져 있으면 50개까지 모아 두었다 다시 보냄), **이 탭 진단**(답변·질문을 몇 개 찾는지).
- 서버(`kit/serve.py`): 이 확장의 고정 ID(`idefgkkfmkgofakkaapjnafeleebnfla`, manifest `key`)만 `/api/ingest`에 허락. 다른 확장·사이트·다른 경로는 그대로 막음. `session`(대화 묶음)·`question`(앞 질문) 받음.

## 확인한 것

- 가짜 claude.ai 화면 점검 `mock_check.js`: 9/9 통과 (`mock_results.json`). 이미 있던 답은 안 보냄, 끝난 글 전체만, 질문·대화 묶음, 멈춤·다시 켜기, claude.ai 페이지가 직접 보내는 요청 막힘.
- 서버 시험 `tests/test_study.py`: 다른 확장 403, 이 확장도 다른 경로 403, 이 확장의 답변+질문 추가.

## 확인하지 못한 것 (사용자 확인이 필요)

- **실제 claude.ai 화면 구조.** 답변·질문을 찾는 규칙(`content.js`의 `SEL`)은 추정이다. 틀리면 팝업 진단에 '못 찾음'이 나온다.
- 답변 안의 버튼 글자(복사 등)가 함께 들어가는지.
- 엣지에서의 동작 (크롬 계열이라 같을 것으로 보지만 확인 안 함).

## 사용자 시험 순서

1. 크롬 주소창에 `chrome://extensions` (엣지는 `edge://extensions`) → 오른쪽 위 **개발자 모드** 켜기 → **압축해제된 확장 프로그램을 로드합니다** → `concept-chart/extension` 폴더 선택.
2. claude.ai 탭을 새로 고침 → 툴바의 THYNK 아이콘 → **이 탭 진단**에 답변·질문 개수가 0이 아닌지 확인.
3. claude.ai에서 질문 10개를 평소처럼 (짧은 답, 긴 답, 코드 답 섞어서).
4. `python experiments/2026-11-13-web-extension/check.py --since <시작 시각 UTC>` → 숫자를 대화창에 붙여 주기.
