# 설계 워크시트 — 개념 차트

양식: AI:GO 개인 프로젝트 OT 슬라이드의 **5단계**(문제정의 → 업무 설계 → AI 활용 → 검증·판단 → 완결).
**주의:** 원본 워크시트 파일은 찾지 못했다. 슬라이드에서 확인한 단계와 질문만 썼고, 칸별 문구(#1~#16)를 지어내지 않았다. 원본과 다르면 그 양식으로 옮긴다. 이 양식이 사용자가 말한 기획서인지도 추정이다.

## 1. 문제정의 — 누구의 어떤 문제를 왜 해결하는가

| 질문 | 답 |
|---|---|
| 누구의 일인가 | CLI나 채팅 LLM으로 개발·공부하는 사람 |
| 지금은 어떻게 하나 | AI 답변을 읽다가 모르는 용어가 나오면 다시 묻거나 검색하고, 대화가 끝나면 잊는다 |
| 어디가 불편한가 | 답변마다 용어가 흩어져 무엇을 공부해야 할지 모른다. AI 설명이 맞는지 확인할 근거도 없다 |
| 무엇이 달라지면 좋은가 | 내 AI 답변에서 공부할 개념만 골라 주고, 출처가 확인된 설명으로 공부한 뒤 이해 여부를 표시할 수 있다 |

**한 문장:** AI 답변을 받은 사람이 그 답변을 이해하도록, 답변 속 개념을 골라 근거가 확인된 공부 노트로 바꿔 주는 도구.

## 2. 업무 설계 — 일의 순서와 AI가 맡을 자리

| 순서 | 일 | 맡는 쪽 | 왜 |
|---|---|---|---|
| 1 | AI 답변 모으기 | 코드 | 훅·붙여넣기·파이프·내보내기 파일. 판단할 것이 없다 |
| 2 | 낱말 뽑기 | 코드(Kiwi) | 같은 입력이면 항상 같은 결과가 나와야 한다 |
| 3 | 공부할 개념 가르기 | **규칙 먼저, 애매하면 LLM, 최종은 사용자** | 일상어 구분은 규칙만으로 부족하지만, LLM만 믿으면 오탐이 많다(실측) |
| 4 | 정의 찾기 | 코드(위키백과) | 출처가 있어야 믿을 수 있다 |
| 5 | 쉬운 설명·요약 | **로컬 LLM** | 문장을 쉽게 바꾸는 일은 규칙으로 못 한다 |
| 6 | 설명이 근거와 맞는지 확인 | 코드(`verify_note`) | 같은 LLM에게 검사를 맡기지 않는다 |
| 7 | 이해 여부 판단 | 사용자 | 사람만 안다 |

**범위:** 개인 PC에서 돌아가는 로컬 프로토타입. 계정·서버 배포·디자인 확정은 이번 범위가 아니다.
**결과물 수준:** OT의 Level 3(화면과 LLM 연결). Level 4(링크로 다른 사람이 사용)는 설치 방식을 정한 뒤 진행한다.

## 3. AI 활용 — 무엇을 주고 무엇을 시키는가

- **모델:** `qwen3:4b` (Ollama, 약 2.5GB, 모델 페이지 기준 Apache 2.0). EXAONE 3.5는 한국어에 강하다는 평이 있지만 비상업 라이선스라 서비스화 목표에 맞지 않아 제외했다. 한국어 품질을 모델끼리 비교하지는 않았다.
- **비용:** API 비용 없음. 전기와 PC 자원만 쓴다. 대화 내용은 이 PC 밖으로 나가지 않는다. 밖으로 나가는 것은 위키백과 검색어(개념 이름)뿐이다.
- **입력:** 근거 문장(출처, 내 대화)만. **출력:** JSON 스키마로 고정(`kit/study_worker.py`).
- **시키지 않는 것:** 근거 없는 설명, 사실 판정, 순위 결정.
- **돌발 상황:** LLM이 없거나 고장 나면 출처 문장만 보여 준다. 근거가 없으면 "찾지 못했어요"라고 쓰고 비워 둔다.
- **파인튜닝:** 하지 않기로 했다. 아래 4절과 `docs/DECISION_LOG.md` 참고. 근거 대조를 통과하는 양을 늘려야 할 때 다시 본다.

## 4. 검증·판단 — 결과를 믿어도 되는지 가리는 기준

| 대상 | 기준 | 지금 값 | 믿을 수 있는 정도 |
|---|---|---|---|
| 공부 개념 정밀도 | 보여 준 것 중 정답 비율 | 관문 없음 0.28 → 조정용 0.98, **처음 보는 낱말 0.92** | 정답은 사용자가 아닌 Claude가 표시. 처음 보는 쪽도 LLM 질문의 예시에 일부 낱말을 넣어 조금 낙관적이다 |
| 공부 개념 재현율 | 정답 중 보여 준 비율 | 처음 보는 낱말 **0.53** | 오탐을 막으려고 일부러 낮췄다. 후보 목록과 "공부할 개념이에요" 버튼으로 보완 |
| 답변 요약 | 원문 문장만 표시 | 구조로 강제, 테스트 있음 | 새 문장이 생기지 않는다. 어떤 문장을 고를지는 LLM 판단 |
| 쉬운 설명 | 근거 한 문장 대조 + 두 번째 확인 | 생성 내용을 직접 읽으며 발견한 오류를 회귀 시험으로 고정 | 전수 평가는 아니다. 관계를 틀리게 쓴 문장이 남을 수 있어 근거를 항상 함께 표시 |
| 틀린 뜻 차단 | 분야 판정 + 대상 판정 | 고정 사례 14건 중 대상 판정 12건 맞음, 분야 판정 18건 중 18건 | 사례는 Claude가 만들었고 표본이 작다 |

**제약 (할루시네이션 방지):** 자세한 목록은 `docs/CONSTRAINTS.md`. 코드와 `tests/test_study.py`로 강제한다.

### 모델을 넣었을 때와 뺐을 때

| 상황 | 표기 합치기 모델 없음 | 파인튜닝 r2 켬 | 개념 관문 없음 | 개념 관문 켬 |
|---|---|---|---|---|
| 내 대화에서 같은 쌍 맞힘 (4쌍 중) | 0 | 1 | - | - |
| 내 대화에서 잘못 합침 (143쌍 중) | 0 | 약 43 | - | - |
| 공부 목록 정밀도 (Claude 표시 기준) | - | - | 0.28 | 처음 보는 낱말 0.92 |
| 메모리 | 추가 없음 | PyTorch·모델 450MB | - | 규칙은 추가 없음 |

결론: 표기 합치기 모델은 끄고, 개념 관문을 켠다. 합치기 모델은 공개 용어집에서는 효과가 있었지만(AP 0.72 → 0.81, 로지스틱 회귀 기준), 내 대화에서는 맞힌 것보다 잘못 합친 것이 훨씬 많았다.

## 5. 완결 — 다른 사람이 실제로 쓸 수 있는가

```
python dev.py app      # 화면 + 서버 + 로컬 LLM → http://localhost:8765
```

입력 경로(`docs/COMMANDS.md`), API 계약(`docs/API.md`), 설치·삭제 방법(`SETUP.md`).

### 화면 구성 — 공부하는 사람의 순서대로

| 화면 | 사용자가 하는 일 | 왜 이렇게 |
|---|---|---|
| **오늘 공부** (첫 화면) | 오늘 볼 7개를 고른다 | 413개를 보여 주면 시작을 못 한다. 할 일이 정해져 있어야 한다 |
| **개념 노트** | 설명 → 내 대화 → 빈칸 문제 → 이해 표시 | 위에서 아래로 읽으면 공부 순서가 된다. 버튼은 끝에 둬서 읽고 난 뒤 누른다 |
| **답변 읽기** | 답변을 붙여넣거나 고르고, 표시된 개념을 눌러 뜻을 본다 | AI 답변을 이해하는 것이 서비스 목적이라 원문에서 바로 노트로 간다 |
| **전체 개념** | 찾기, 숨긴 낱말 되돌리기 | 자동 판단이 틀려도 사용자가 고칠 수 있어야 한다 |

- 처음 쓰는 사람도 쓰도록: 메뉴는 3개, 전문 용어·설정 화면 없음, 빈 화면에는 다음에 할 일을 적는다.
- 믿을 수 있는 정도를 항상 표시: `AI 요약 · 근거 확인됨`, `출처 문장`, `설명 준비 중`. 근거 문장은 "근거 문장 보기"로 펼친다.

### 나누어 둔 구조

```
입구(훅·붙여넣기·파이프·내보내기) → 인박스(파일) → 서버(kit/serve.py + study_api.py) → API(docs/API.md) → 화면(app/)
                                                     ↕ jobs 표
                                         모델 작업자(kit/study_worker.py, 별도 프로세스) → LLM(kit/llm.py)
```

화면을 통째로 바꿔도 `docs/API.md`만 지키면 서버를 건드리지 않는다. LLM을 바꿔도 `kit/llm.py`만 고친다. 모델 프로세스가 죽어도 서버와 화면은 그대로 응답한다.
