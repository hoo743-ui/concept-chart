# 디자인 가이드 — 피그마로 화면 그리기

사용자 결정(11-11): 서비스 화면은 사용자가 피그마로 직접 디자인한다 (D7 "디자인·UI/UX는 사용자가 나중에 직접"). 이 문서는 그때 지킬 것과, 디자인을 코드로 옮길 때 맞출 데이터를 정리한다.
배치 아이디어는 `docs/WORKSHEET.md` 5절 "개념 노트 배치 아이디어", 데이터 계약은 `docs/API.md`.

## 1. 바꾸면 안 되는 것 (기획서의 원칙)

디자인은 자유롭게 바꿔도 되지만, 아래는 서비스의 약속이라 화면에서도 지킨다.

| 원칙 | 화면에서 | 근거 |
|---|---|---|
| 믿을 수 있는 정도를 항상 보여 준다 | 설명 문장마다 `근거 확인됨` · `출처 문장` · `설명 없음` 표시. 색만으로 구분하지 않고 글자를 함께 둔다 | `docs/CONSTRAINTS.md`, 할루시네이션 방지 |
| 근거 없는 설명은 지어내지 않는다 | 설명이 없으면 빈 상태 문구("아직 믿을 만한 설명을 찾지 못했어요")를 디자인한다. 예시 문장을 채운 시안은 실제와 다르다 | API `note.easy`가 `null`일 수 있다 |
| 출처를 누를 수 있다 | 출처 문장 옆에 원문 링크(위키백과 등) | `sources:[{text, url}]` |
| 자동 판단은 사용자가 고칠 수 있다 | '공부할 개념인가요? 맞아요 · 아니에요', 숨긴 낱말 되돌리기 | 사용자 판단이 관문보다 앞선다 |
| 할 일이 정해져 있다 | 첫 화면은 오늘 볼 것만. 전체 목록을 첫 화면에 펼치지 않는다 | 기획서 5절 |
| 읽고 난 뒤 누른다 | 이해 표시 버튼은 노트 끝에 | 기획서 5절 |
| 챗봇은 기록으로만 답한다 | 채팅 화면에 "내 공부 기록에서만 답해요" 안내, 답마다 개념 노트 링크. 일반 질문 입력을 유도하는 문구는 넣지 않는다 | 기획서 2절 '내 공부 기록에 묻기' |

## 2. 화면 목록 (지금 있는 것)

프레임 이름은 아래 화면 이름을 그대로 쓰면 코드와 맞추기 쉽다. 경로는 `app/app.js`의 주소.

| 프레임 | 주소 | 보여 줄 데이터 (API 필드) | 꼭 그릴 상태 |
|---|---|---|---|
| 오늘 공부 (첫 화면) | `#/` | `today.groups[]`: `question`(처음 만난 내 질문), `items[]`(개념 요약 3개까지), `more[]`(접힌 '더 보기', `extra`는 맨 끝). `counts`: `shown`·`left`·`known` | 처음 쓸 때(개념 0개), 보통, 다 끝냄(left 0), '더 보기' 펼침 |
| 개념 노트 | `#/c/{id}` | `label`, `field`(분야 꼬리표), `origin.question`, 쉬운 설명 `note.easy`+근거, 출처 `definition`·`sources`, 내 대화 `records[]`, 빈칸 문제 `practice`, 함께 나온 개념 `related[]`, 진도 `progress`, 내 판단 `gate.by=user` | 설명 준비됨 / 출처 문장만 / 설명 없음 / 준비 중 / 뜻이 다름(`wrong_sense`), 빈칸 문제 있음·없음, 내 판단 있음·없음 |
| 답변 목록 | `#/answers` | `answers[]`: `preview`, `ts`, `source` + 붙여넣기 칸 | 답변 0개, 붙여넣기 오류 |
| 답변 읽기 | `#/a/{id}` | `question`, `summary.points[]`(원문 문장), `terms[]`(이 답변의 개념), 원문 `text`(개념에 표시) | 요약 없음 / 요약 준비 중 / 요약 있음 |
| 전체 개념 | `#/all` | `concepts.items[]`(개념 요약), 찾기 | 결과 0개 |
| 숨긴 낱말 | `#/hidden` | `items[]`, `gate.candidate`(후보 표시), '공부할 개념이에요' | — |
| 내 공부 기록에 묻기 | `localhost:8766` (따로 도는 앱) | 질문 예시 4개, 답 문단 `text[]`, 링크 `links[]` | "기록에 없어요" 답, 개념 차트가 꺼져 있을 때 |

공통: 위 메뉴 3개(오늘 공부 · 답변 · 전체 개념), 상태 줄(`/api/health`: AI 연결, 준비 중 작업 수).

### 개념 요약 카드 (여러 화면에서 같은 부품)

`label` · `field` 꼬리표 · 한 줄 설명 `line` + 믿음 표시 `line_kind` · 진도 `progress` · (오늘 공부에서는) 처음 만난 질문.
`line`이 비면 "아직 믿을 만한 설명을 찾지 못했어요." 실제 데이터에서 설명이 붙은 비율은 11-11 기준 0.396이라, **설명 없는 카드가 흔하다**는 것을 시안에 반영한다.

## 3. 부품과 변형 (피그마 컴포넌트 제안)

| 컴포넌트 | 변형(Variant) | 데이터 |
|---|---|---|
| 믿음 표시 `TrustTag` | `ai_checked`(근거 확인됨) · `source`(출처 문장) · `none`(설명 없음) · `pending`(준비 중) · `own`(내 대화 문장) | `line_kind`(ai_checked·source·none), `note.status`(none이면 준비 중), `own`은 `records[]` 문장에 붙인다 (API 값이 아니라 화면 구분) |
| 개념 카드 `ConceptCard` | 진도 `new`·`review`·`known` × 설명 있음·없음 × `extra` | 개념 요약 |
| 질문 묶음 `QuestionGroup` | 펼침·접힘, '더 보기' 개수 | `groups[]` |
| 분야 꼬리표 `FieldTag` | 분야 있음 / '분야 미정' | `field` |
| 판단 줄 `FeedbackRow` | 판단 전(맞아요 · 아니에요) / 판단 후(내 판단 + 지우기) | `gate.by` |
| 진도 버튼 `ProgressActions` | 이해했어요 · 다시 볼게요 | `progress` |
| 빈 상태 `EmptyState` | 처음 사용 / 결과 없음 / 기록 없음 | — |

컴포넌트 이름과 변형 이름을 영어로 두면 피그마 MCP로 읽어 코드로 옮길 때 그대로 쓸 수 있다.

## 4. 크기·접근성

- 프레임: 넓은 화면 1440, 좁은 화면 390 (휴대폰). 배치 아이디어(12칸, 본문 8 + 옆 4, 좁으면 한 줄로 쌓기)는 `docs/WORKSHEET.md` 5절.
- 글자: 한국어 본문은 16px 이상, 줄 간격 1.6 안팎 (긴 설명을 읽는 화면).
- 대비: 글자와 배경 대비 4.5:1 이상. 믿음 표시는 색 + 글자 + (가능하면) 모양으로.
- 버튼·링크 누르는 영역 44px 이상.
- 밝은·어두운 화면 둘 다 (지금 `app/style.css`도 둘 다 지원).

## 5. 디자인을 코드로 옮기는 순서 (나중에)

1. 피그마 MCP로 프레임을 읽는다 (사용자가 링크를 준다).
2. 화면만 바꾼다: `app/atelier.html`·`app/atelier.css`·`app/atelier.js`·`app/atelier-chat.js` (11-13부터 서버 첫 화면. `app/index.html`은 이 파일로 넘기기만 하고, 예전 화면은 `app/classic.html`). 서버·API·판정·근거 대조는 그대로 (`docs/API.md` 계약).
3. `python dev.py check`(화면 점검 `tests/check_app.js` 포함)로 확인하고, 화면 캡처를 사용자에게 보여 확인받는다.
4. 디자인에 API에 없는 데이터가 필요하면 만들기 전에 사용자에게 알린다 (지어낸 값으로 채우지 않는다).
