# 제품 전략 — 왜 개념 차트인가 (2026-11-12 초안)

사용자 브리프 "서비스 존재 이유 중심의 전체 웹서비스 재설계"의 1~4단계(진단·전략·UX·디자인) 문서다. 5단계(구현)는 이 문서의 **1차 범위**를 사용자가 확인한 뒤에 시작한다.
기준: 기존 API 계약(`docs/API.md`)·데이터·판정 로직은 바꾸지 않는다. 데이터에 없는 관계·상태·인사이트는 만들지 않는다(`docs/CONSTRAINTS.md`).

## 1. 진단 — 지금 무엇이 있고 무엇이 없나

| 화면 | 지금 하는 일 | 사용자가 얻는 것 | 빈 곳 |
|---|---|---|---|
| 오늘 공부 `#/` | 이해함이 아닌 개념을 처음 만난 질문별로 묶음 | 오늘 볼 것 | 왜 지금 이것인지(재발견 이유)가 없다 |
| 개념 노트 `#/c/{id}` | 쉬운 설명·정의·출처·처음 만난 질문·관련 개념·기록·빈칸 문제·진도 | 한 개념의 깊이 | 이 개념의 **나의 시간 흐름**(처음→다시 나옴→열어 봄→표시)이 한 줄로 안 보인다 |
| 답변 기록 `#/answers` | 최근 답변 목록·원문 | 다시 읽기 | 검색 없음(API가 최근 k개만), 답변에서 나온 개념이 목록에 안 보임 |
| 전체 개념 `#/all` | 검색·분야·상태·정렬·분야 관계 그래프(처음 만난 답변 기준) | 내 지식 라이브러리 | — (이번 작업에서 만듦) |
| 숨긴 개념 `#/hidden` | 사용자 판단 되돌리기 | 정확도 통제 | — |
| 기록에 묻기 `:8766` | 학습 순서·분야별·최근·'X 했던가?' | 기록에 대한 질문 | 일반 질문엔 답 못 함(설계상, 지어내지 않기 위해) |

실제 데이터(DB 사본, 11-12) 관찰: 공부할 개념 291개, 모두 진도 `new`(이해함 0), 분야는 `정보·통신`·`분야 미정`이 대부분, 질문 225개 중 31개는 붙여 넣은 글·에이전트 메시지 같은 '봉투'. → **진도 데이터가 아직 거의 없어서 '무엇을 아는지'를 보여 줄 근거가 약하다.** 처음 몇 주는 '쌓이는 것'과 '다시 나온 것'이 가장 믿을 만한 신호다.

## 2. 제품 전략

**한 문장**: 흩어진 AI 질문을 나만의 지식으로 축적하고, 연결하고, 다시 발견하는 개인 학습 기록 공간.
**파는 것**: AI가 아니라 "내가 공부한 시간이 지식으로 남는다"는 경험. (사용자 결정 11-12)

| 일반 AI 챗봇 | 개념 차트 |
|---|---|
| 묻고 답 받기 → 대화 기록 → 잊으면 다시 묻기 | 질문을 개념으로 축적 → 과거 지식과 연결 → 학습 과정 재발견 |
| 답변 중심 | 지식 성장 중심 |
| 모델이 아는 것 | **내가 만난 것**(출처·처음 만난 질문·내 판단이 붙음) |

**주요 사용자**: AI(Claude Code 등)로 매일 공부·작업하는 사람. 1차는 개발·데이터 공부(실데이터가 그 분야). 수준별(고등학생~연구자) 확장은 [사용자 계획, 출력 검증 후].

**가치 5개를 화면에 대응**

| 가치 | 근거 데이터 | 화면 |
|---|---|---|
| Capture 기록 | 훅 → 인박스 → 답변·질문 | 답변 기록, 첫 화면의 '쌓인 양' |
| Organize 정리 | 개념 관문·분야 꼬리표·쉬운 설명 | 개념 노트, 라이브러리 |
| Connect 연결 | `related[]`(노트), `origin.answer`(같은 답변에서 처음 만남), 답변의 `terms[]` | 노트의 관련 개념, 라이브러리 관계 그래프 |
| Rediscover 재발견 | `origin.ts`(처음) vs `last_seen`(최근), `history`(열어 봄·표시) | 오늘 공부의 '다시 나온 개념', 노트의 타임라인 |
| Grow 성장 | 개념 수·설명 붙은 비율·진도·분야 분포 | 라이브러리 통계, 오늘 공부의 짧은 요약 |

**핵심 지표 (사용자 결정 11-12)**와 지금 잴 수 있는지

| 지표 | 지금 데이터로 | 필요한 것 |
|---|---|---|
| 과거 학습 기록을 다시 열어본 비율 | 부분: `history`는 개념마다 마지막 '열어 봄' 하나뿐 → "한 번 이상 열어 본 개념 비율"만 가능 | 열기 횟수 기록 (API 제안 P3) |
| 과거 개념 → 새 개념으로 이동한 비율 | 불가: 화면 이동을 기록하지 않음 | 이동 기록 (API 제안 P4, 이 PC에만 저장) |
| 학습 기록이 개념 노트로 축적되는 비율 | 가능(근사): `line_kind != none` 비율 = 설명이 붙은 개념 비율 | — |
| 재방문 사용자의 라이브러리 탐색 빈도 | 불가 | 방문·탐색 기록 (API 제안 P4) |

지표는 사용자 본인에게 보여 주는 '나의 학습' 숫자로만 쓰고, 밖으로 보내지 않는다(로컬 앱).

## 3. UX — 사용자 여정과 화면

### 여정

1. **처음 방문(기록 0)**: "공부한 내용이 사라지지 않도록." + 3단계 그림(질문 → 개념 → 나만의 지식) + 연결 방법(훅 설치·붙여넣기). 마스코트는 여기서 크게 한 번.
2. **공부하고 질문할 때**: Claude Code에서 평소처럼 묻는다. 개념 차트는 뒤에서 개념을 모은다(훅). 기록에 묻기는 "내 기록에 대한 질문" 전용.
3. **다시 왔을 때(일주일 뒤)**: 오늘 공부 상단에 **"예전에 만난 개념이 최근 대화에 다시 나왔어요"**(처음 만난 날이 오래됐고 `last_seen`이 최근인 개념) — 재방문 이유. 그 아래 질문별 묶음.
4. **쌓였을 때(한 달 뒤)**: 라이브러리에서 분야 분포·설명 붙은 비율·관계 그래프. 노트마다 "나와 이 개념의 시간" 타임라인.

### 화면별 — 해결하는 문제와 1차 변경 (모두 기존 URL 유지)

| 화면 | 해결하는 문제 | 1차(지금 API로 가능) | 근거 필드 |
|---|---|---|---|
| A. 오늘 공부 (My Learning Desk) | 오늘 뭘 하지? 예전 것 잊음 | ① 다시 나온 개념(재발견) ② 처음 방문 빈 상태를 가치 소개로 ③ 쌓인 양 한 줄(개념 N·설명 붙은 비율·열어 본 개념 N) ④ 기록에 묻기 입구 | `origin.ts`, `last_seen`, `line_kind`, `history` |
| B. 개념 노트 (Knowledge Journal) | 이 개념과 나의 관계가 안 보임 | ⑤ 타임라인: 처음 만남(`origin`) → 다시 나온 대화(`records[]`) → 마지막으로 열어 봄·진도 표시(`history`) — 기록 있는 것만 | `origin`, `records`, `history` |
| C. 답변 기록 (Learning Archive) | 예전 질문을 못 찾음 | ⑥ 답변 카드에 그 답변에서 처음 만난 개념(이미 받은 개념 목록의 `origin.answer`로 묶음, 추가 요청 없음) ⑦ 지금 불러온 목록 안에서 찾기 | `origin.answer` |
| D. 전체 개념 (Personal Knowledge Library) | 수백 개 중에서 찾기 | 이미 구현. ⑧ '다시 나온 개념' 거르기 추가 | 위와 같음 |
| E. 기록에 묻기 (Thinking Space) | 내 기록에 대해 묻기 | 이번에 구현(마스코트·이어지는 대화·후속 질문) | `/api/ask` |

**1차 구현 상태 (11-12, 사용자 승인 후)**: ①~⑧ 모두 `app/atelier.*`에 반영. API·서버·데이터는 그대로.
'다시 나온 개념' 규칙: 대화 2개 이상(`sessions`)에 나왔고, 처음 만난 날(`origin.ts`)과 가장 최근(`last_seen`)이 달력으로 하루 이상 다르고, 최근 14일 안. 실데이터 사본에서 60개.
⑦은 이미 있던 '불러온 답변 안에서 찾기'에 개념 이름을 더했다. 시험: `tests/e2e/atelier.spec.js` M24~M29.

### 2차 이후 — API·데이터 변경이 필요해서 **제안만** (승인 전 손대지 않음)

| 번호 | 무엇 | 왜 필요한가 | 영향 |
|---|---|---|---|
| P1 | 답변 검색 API (`/api/answers?q=`) | 지금은 최근 k개만 받아 옛 질문을 못 찾음 | 읽기 API 추가, 기존 응답 그대로 |
| P2 | 목록에 `related` 개수 또는 관계 묶음 API | 관계 그래프를 '처음 만난 답변'보다 넓게(같은 답변에 함께 나온 개념) 그리려면. 노트 API는 열 때마다 '열어 본 기록'을 남겨서 목록에서 부를 수 없음 | 읽기 API 추가 |
| P3 | 열기 횟수(`history`에 `count`) | 지표 1, '자주 다시 본 개념' | 응답에 필드 추가 |
| P4 | 화면 이동·방문 기록(이 PC의 DB에만) | 지표 2·4 | 기록 API 추가, 개인 데이터 증가 |
| P5 | 서버 연결 대기열 늘리기(`request_queue_size`) | 글꼴 조각을 한꺼번에 받을 때 연결 거절 실측(시험 환경) | `kit/serve.py` 한 줄 |
| P6 | 봉투 질문(붙여 넣은 글·에이전트 메시지)을 질문으로 저장하지 않거나 표시 | 처음 만난 질문 자리에 태그가 보임 (화면에서 이름만 바꿔 보여 주는 중) | 수집 로직 — 판정 로직 변경이라 사용자 결정 |

### 하지 않는 것

- 근거 없는 학습 성향·능력 판정("당신은 ○○형 학습자"), 무작위 복습 알림, 데이터 없는 연결선·장식 그래프.
- 퀴즈는 기존 `practice`(출처 문장 빈칸)만. 새 문제 생성 없음.

## 4. 디자인

COGNITIVE ATELIER 그대로(`docs/DESIGN_GUIDE.md`, Figma "Cognitive Atelier" 페이지). 화면마다 성격을 다르게:
오늘 공부 = 책상(재발견 띠가 맨 위, 비대칭), 노트 = 저널(긴 글 읽기 폭 + 여백의 타임라인), 답변 기록 = 서가(날짜 색인), 라이브러리 = 색인·지도, 묻기 = 대화 지면 + 마스코트.
마스코트는 처음 방문·묻기·빈 상태에서만 나온다(모든 화면에 크게 두지 않음).
문구: 메인 "공부한 내용이 사라지지 않도록." 서브 "질문은 기록이 되고, 기록은 개념이 되고, 개념은 나만의 지식이 됩니다." 영어 장식 문구는 쓰지 않는다.

## 5. 최종 질문에 대한 현재 답 (가설 — 사용자 확인·실사용으로 검증)

1. **왜 챗봇 대신?** 챗봇은 대화가 끝나면 흩어진다. 개념 차트는 같은 질문들에서 개념을 뽑아 출처·처음 만난 질문·내 판단과 함께 남긴다. 챗봇을 대체하지 않고 **챗봇 뒤에서 쌓는다**.
2. **어떤 문제?** 잊음, 흩어짐, 연결 안 됨, 내가 뭘 아는지 모름 — 이 중 앞의 셋은 지금 데이터로, 넷째는 진도 표시가 쌓여야 답한다.
3. **처음 방문에 가치 이해?** 1차 ②가 들어가야 '예'. 지금은 기록 0이면 빈 목록뿐이다.
4. **일주일 후 재방문 이유?** 1차 ①(다시 나온 개념)이 그 이유. 지금은 없다.
5. **한 달 후?** 라이브러리·타임라인에서 쌓인 것을 보는 경험. 진도 표시가 쌓이지 않으면 약하다 — 진도 표시를 쉽게 만드는 것이 관건.
6. **데이터가 쌓일수록 가치가 커지나?** 예: 개념·관계·재발견 후보가 모두 기록량에 비례한다.
7. **독자적 경험?** '내가 만난 개념의 시간과 출처'는 모델이 줄 수 없다.
8. **한 문장**: "AI와 나눈 공부가 사라지지 않고, 개념으로 쌓이고, 다시 나타난다."
