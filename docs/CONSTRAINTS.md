# 제약 조건 — 틀린 내용을 보여 주지 않기 위한 규칙

사용자 요구(11-09): 오탐과 결과 오류가 웬만해선 없어야 하고, 할루시네이션이 생기지 않게 계속 제약을 걸 것.
새 기능을 넣을 때 이 목록을 지키고, 코드로 강제할 수 있는 것은 `tests/test_study.py`에 시험을 더한다.

## 생성 문장 (LLM)

| # | 규칙 | 강제하는 곳 |
|---|---|---|
| 1 | **요약은 LLM이 번호만 고른다.** 화면의 문장은 답변 원문이고 새 문장이 생기지 않는다 | `study_worker.run_summary`, 시험 있음 |
| 2 | 출력은 JSON 스키마로 고정한다. 형식이 틀리면 버린다 | `llm.Ollama.json` |
| 3 | 쉬운 설명은 근거 **한 문장**에서만 만든다. 여러 문장을 조합하지 못하게 한다 | `run_note` |
| 4 | 명사·숫자·영문이 그 문장에 모두 있어야 한다. 낱말 일부만 맞아도 거절한다 | `study_worker.strict_ok`, 시험 있음 |
| 5 | 코드 대조를 통과해도 LLM이 다른 프롬프트로 뒷받침된다고 답해야 저장한다 | `run_note`, 시험 있음 |
| 6 | 탈락하면 LLM 문장을 버리고 출처 문장을 그대로 보여 준다 | `run_note`, `app/app.js` |
| 7 | 출처가 다른 분야이거나 이름만 같은 다른 대상이면 정의와 설명을 모두 숨긴다 | `run_note`, `study_api.detail`, 시험 있음 |
| 8 | 근거가 없으면 설명을 만들지 않고 "찾지 못했어요"라고 쓴다 | `app/app.js`, 시험 있음 |
| 8-1 | LLM이 대화 맥락 설명, 기억할 점, 퀴즈를 쓰지 않는다. 실제로 지어낸 문장이 나와 뺐다. 확인 문제는 출처 문장의 빈칸 채우기다 | `study_api.practice`, 시험 있음 |

**알려진 한계:**
- 쉬운 설명은 낱말이 모두 원문에 있어도 관계를 틀리게 쓸 수 있다. 두 번째 확인으로 줄일 뿐 없애지는 못한다. 그래서 "근거 문장 보기"와 출처 링크를 항상 둔다.
- 위키백과 출처 자체가 틀렸다면 그대로 나온다.
- 같은 기술 분야에서 이름만 같은 대상은 놓칠 수 있다 (시험 사례 14건 중 `LoRa` 무선 통신 1건을 분야·대상 판정으로 못 잡음).
- 답변 요약은 원문 그대로지만, 어떤 문장을 고를지는 LLM 판단이라 중요한 문장이 빠질 수 있다. 원문이 항상 아래에 있다.
