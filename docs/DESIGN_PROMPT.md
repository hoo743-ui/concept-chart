# 웹디자인 프롬프트 형식

디자인 AI(Claude, Google Stitch, v0 등)에 그대로 붙여 넣는 글이다. `[ ]` 칸만 바꿔 쓴다.
화면 구조·상태값은 `app/`와 `docs/API.md` 기준이다 (2026-11-10). 계약이 바뀌면 이 문서도 고친다.

## 쓰는 법

1. 아래 **A. 공통 설명**은 매번 그대로 붙인다.
2. **B. 화면별 요청**에서 이번에 만들 화면 하나만 골라 이어 붙인다. 한 번에 화면 하나만 요청해야 결과가 흔들리지 않는다.
3. **C. 분위기 칸**을 채운다. 비워 두면 AI가 마음대로 정한다.
4. 마음에 드는 시안이 나오면 HTML/CSS를 Claude Code에 주고 "`app/`에 옮겨 줘"라고 한다. 이때 `api.js`(서버와 주고받는 부분)는 바꾸지 않는다.

---

## A. 공통 설명 (매번 붙임)

```
너는 웹 UI 디자이너다. 아래 앱의 화면 하나를 디자인한다.

[앱]
- 이름: 개념 차트
- 하는 일: 사용자가 AI(Claude 등)와 나눈 대화에서 공부할 만한 개념을 골라, 출처가 붙은 짧은 공부 노트로 보여 준다.
- 사용자: AI에게 자주 묻는 학생·개발자. 한국어 화면.
- 실행 환경: 사용자 컴퓨터에서 도는 앱 창(로컬 서버 + 웹뷰). 인터넷이 없어도 열린다.

[지켜야 할 것]
- 결과물: HTML 하나 + CSS. 프레임워크(React, Tailwind 등)와 외부 글꼴·아이콘 CDN을 쓰지 않는다.
- 색은 CSS 변수로만 쓴다: --bg --card --ink --muted --line --accent --accent-ink --mark --ok --warn
  밝은 모드와 어두운 모드(prefers-color-scheme: dark) 값을 둘 다 정한다.
- 본문 폭 최대 720px, 휴대폰 폭(360px)에서도 가로 스크롤이 없어야 한다.
- 한국어 줄바꿈: word-break: keep-all. 글꼴은 system-ui, "Malgun Gothic", "Apple SD Gothic Neo".
- 키보드로 모든 버튼에 갈 수 있고, 초점 표시가 보인다. 글자와 배경 대비는 WCAG AA 이상.
- 상단 메뉴 3개 고정: 오늘 공부 / 답변 읽기 / 전체 개념.
- 내용을 지어내지 않는다. 설명이 없는 상태는 빈칸·안내 문구로 보여 주고, 가짜 설명을 채우지 않는다.
  (이 앱은 출처로 확인한 문장만 보여 주는 것이 핵심이다)
- 예시 데이터는 아래 [예시 데이터]만 쓴다.

[분위기]  ← C 칸에서 채운 내용
```

## B. 화면별 요청 (하나만 골라 붙임)

### B1. 오늘 공부 (첫 화면)

```
[화면] 오늘 공부
- 위: 제목 "오늘 볼 개념 n개"와 숫자 요약 (공부 목록 n개 · 이해함 n개 · 남음 n개)
- 목록: 개념 카드 최대 7개. 카드 = 개념 이름(굵게) + 한 줄 설명 + 작은 표시
  - 한 줄 설명의 종류: "출처 확인"(출처 문장) / "AI 설명·근거 대조 통과" / 설명 없음(비워 둠)
  - 진도 표시: 새 개념 / 다시 볼 것 / 이해함
- 카드를 누르면 개념 노트로 간다.
- 빈 상태: "AI 답변이 쌓이면 여기에 공부할 개념이 나타나요." + "AI 답변 붙여넣기" 링크
[예시 데이터]
- 형태소 | 뜻을 가진 가장 작은 말의 단위. | 출처 확인 | 새 개념
- 교차검증 | (설명 없음) | - | 다시 볼 것
- 체크포인트 | 학습 중인 모델의 상태를 저장한 파일. | AI 설명·근거 대조 통과 | 새 개념
```

### B2. 개념 노트

```
[화면] 개념 노트 (개념 하나를 눌렀을 때)
순서대로:
1. "← 오늘 공부" 뒤로 가기, 개념 이름(큰 제목)
2. 정의: 출처 문장 한 줄 + 출처 링크(위키백과 등). 출처가 없으면 "아직 확인된 출처가 없어요"
3. 쉬운 설명: 근거 대조를 통과했을 때만 보인다. 옆에 "근거 문장 보기"를 펼치면 원문 근거 한 문장
4. 빈칸 문제: 출처 문장에서 개념 이름만 ____ 로 가린 문제, "정답 보기" 버튼
5. 내 대화에서: 이 개념이 나온 내 대화 문장 2~3개 (질문은 회색 인용으로)
6. 관련 개념: 둥근 칩 몇 개
7. 아래 버튼: [이해했어요] (주 버튼) / [다시 볼게요]
   그 아래 작은 링크: "공부할 개념이 아니에요 (목록에서 숨기기)"
상태별로 보여 줄 것: 준비 중(불러오는 중) / 근거 없음 / 출처가 다른 분야 뜻이라 비움
[예시 데이터]
- 이름: 형태소
- 정의: 형태소는 뜻을 가진 가장 작은 말의 단위이다. (출처: 위키백과 '형태소')
- 빈칸: ____는 뜻을 가진 가장 작은 말의 단위이다.
- 내 대화: "Kiwi로 형태소 분석을 하면 복합어가 둘로 나뉜다"
- 관련 개념: 품사, 토큰화, 어근
```

### B3. 답변 읽기

```
[화면] 답변 읽기
- 위: 제목 "AI 답변 읽기", AI 답변을 붙여 넣는 큰 입력 칸 + [답변 추가] 버튼
- 아래: 최근 답변 목록. 항목 = 답변 첫 줄 미리보기 + 시각 · 출처(Claude Code / 붙여넣기)
- 답변 하나를 열면: 원문 전체. 원문 안의 공부 개념은 형광펜(--mark)으로 칠하고 누르면 개념 노트로 간다.
  위에 "요약" 상자: 원문에서 고른 핵심 문장 3개 (지어낸 요약이 아님을 작게 표시)
[예시 데이터]
- 미리보기: "형태소 분석기는 문장을 뜻이 있는 가장 작은 단위로…" · 오늘 14:02 · Claude Code
```

### B4. 전체 개념

```
[화면] 전체 개념
- 검색 칸 + 개념 목록 (이름, 나온 대화 수, 진도 표시)
- 맨 아래 "숨긴 낱말 보기" 링크 → 숨긴 목록에서는 "다시 보이기" 버튼
- 수가 많다(수백 개). 한 줄을 낮게, 훑어보기 쉽게.
[예시 데이터]
- 형태소 · 대화 12개 · 새 개념 / 교차검증 · 대화 5개 · 다시 볼 것 / 서버 · 대화 30개 · 이해함
```

### B5. 첫 실행 설정 (설치 직후)

```
[화면] 첫 실행 4단계 (한 단계씩 넘기는 마법사)
1. 확인: 이 컴퓨터에서 쓸 수 있는지 점검 (통과/주의 표시)
2. 받기: 추가 AI(선택). "AI 없이 쓰기"도 같은 크기의 선택지로 둔다. 크기 표시: 약 5.8GB
3. 입력 고르기: Claude Code 대화 / 붙여넣기만
4. 지난 대화 가져오기 동의: 무엇을 읽는지, 컴퓨터 밖으로 보내지 않는다는 문장, [가져오기] / [나중에]
```

## C. 분위기 칸 (채워서 A 끝에 붙임)

```
[분위기]
- 느낌: [예: 조용한 공부 노트 / 밝고 가벼운 / 신문처럼 단정한]
- 주 색(--accent): [예: 남색 #2f5fd0 그대로 / 초록 계열 / AI가 3안 제안]
- 참고하고 싶은 것: [서비스 이름이나 스크린샷 설명. 없으면 "없음"]
- 피하고 싶은 것: [예: 그라데이션, 큰 일러스트, 이모지]
- 시안 개수: [예: 서로 다른 방향 3개]
```

## 결과를 받은 뒤 확인할 것

- 프레임워크·CDN을 쓰지 않았는가 (썼으면 "순수 HTML/CSS로 다시"라고 요청)
- 어두운 모드 값이 있는가
- 360px 폭에서 가로로 넘치지 않는가
- 예시에 없는 설명 문장을 지어 넣지 않았는가
